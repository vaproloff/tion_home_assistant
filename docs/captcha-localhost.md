# Вход в Tion через localhost

С середины октября 2026 сервер Tion принимает капчу (Yandex SmartCaptcha), только если страница с ней открыта по адресу ровно `http://localhost` (без порта). Страница капчи интеграции открывается по адресу Home Assistant (`http://homeassistant.local:8123`, облачный домен и так далее), поэтому проверку не проходит, и интеграция показывает ошибку «Tion не принял капчу». Чтобы войти, на несколько минут входа пробросьте порт 80 своего компьютера на Home Assistant. Как это сделать, описано ниже.

Это касается только входа: новой установки интеграции и повторной авторизации (пароль, капча, код из письма).

**Уже настроенная интеграция продолжает работать. Не удаляйте запись интеграции**: после удаления сущности получат новые `entity_id`, а автоматизации и дашборды перестанут на них ссылаться. Если Home Assistant показывает уведомление «нужна повторная авторизация», откройте его: форма называет причину. «Tion отклонил сохранённую сессию» — войдите заново, даже если устройства пока работают. «Tion больше часа не продлевает сессию» — скорее всего сбой Tion: подождите, с версии 2026.10.1 интеграция продолжает попытки и сама снимает запрос, когда связь восстановится; если он держится больше суток, войдите заново. В версии 2026.10.0 ложный запрос снимала перезагрузка записи: `Настройки` -> `Устройства и службы` -> Tion -> три точки -> `Перезагрузить`.

## Что понадобится

- Компьютер с браузером (Windows, macOS или Linux), с которого вы входите в Home Assistant. С телефона и планшета способ не работает: на них `localhost` означает само устройство.
- Свободный порт 80 на этом компьютере и права администратора: в Windows консоль «от имени администратора» (для `netsh`), на macOS и Linux `sudo`.
- Адрес, по которому браузер открывает Home Assistant. От него зависит способ:
  - `http://...`, например `http://homeassistant.local:8123` или `http://192.168.1.50:8123`: раздел «Home Assistant по http»;
  - `https://...`: облачный домен Keenetic, Nabu Casa, свой домен. Это раздел «Home Assistant по HTTPS-адресу».

В командах ниже `<HA>` — адрес Home Assistant без `http://` и порта (например `homeassistant.local` или `192.168.1.50`), `<IP HA>` — его IP-адрес, `<домен>` — HTTPS-адрес без `https://`, `<пользователь>` — имя пользователя для SSH на Home Assistant. Все способы, кроме `mitmproxy` и Caddy (о них сказано отдельно), слушают только `127.0.0.1`, поэтому Home Assistant не открывается наружу.

## Home Assistant по http

Выберите один способ, затем переходите к разделу «Проверка».

### Windows: встроенный `netsh`

Откройте PowerShell или «Командную строку» от имени администратора и выполните:

```
netsh interface portproxy add v4tov4 listenport=80 listenaddress=127.0.0.1 connectport=8123 connectaddress=<IP HA>
```

Выключить проброс после входа:

```
netsh interface portproxy delete v4tov4 listenport=80 listenaddress=127.0.0.1
```

Правило `netsh` остаётся в Windows и после перезагрузки, поэтому обязательно удалите его этой командой.

### Любая ОС: скрипт `captcha_proxy_local.py`

Нужен Python 3.9 или новее, больше ничего устанавливать не надо. На macOS и Linux:

```
curl -O https://raw.githubusercontent.com/vaproloff/tion_home_assistant/master/docs/captcha_proxy_local.py
sudo python3 captcha_proxy_local.py <HA> 8123
```

В Windows скачайте командой `curl.exe -O ...` (в PowerShell `curl` без `.exe` — другая команда) и запустите `py captcha_proxy_local.py <HA> 8123`. Скрипт пишет в окно, что делает; если порт 80 занят или не хватает прав, он так и скажет. Выключить: Ctrl+C.

### Другие способы: `socat` и SSH (macOS и Linux)

Если `socat` уже установлен (`brew install socat` на macOS, `sudo apt install socat` в Debian и Ubuntu):

```
sudo socat TCP-LISTEN:80,bind=127.0.0.1,fork,reuseaddr TCP:<HA>:8123
```

Если на Home Assistant есть SSH с разрешённым пробросом портов:

```
sudo ssh -L 127.0.0.1:80:localhost:8123 <пользователь>@<HA>
```

Под `sudo` SSH ищет ключи в домашней папке root: при входе по ключу добавьте `-i ~/.ssh/<файл ключа>`. На Home Assistant OS аддоны SSH обычно запрещают проброс (в Advanced SSH & Web Terminal нужен параметр `allow_tcp_forwarding: true`), а сам Home Assistant внутри аддона доступен как `homeassistant:8123`: укажите его вместо `localhost:8123`. Ошибка `administratively prohibited` значит, что проброс на стороне Home Assistant выключен.

Выключить проброс: Ctrl+C или `exit` в этом окне.

## Home Assistant по HTTPS-адресу

Обычный проброс порта (`netsh`, `captcha_proxy_local.py`, `socat`, SSH) здесь не годится: адрес за HTTPS ждёт шифрования и своего имени хоста. Нужен HTTP-прокси: он принимает запросы браузера на `http://localhost` и передаёт их вашему Home Assistant по его HTTPS-адресу. С Tion прокси не связан: капча и вход идут из вашего браузера.

### Скрипт `captcha_proxy_https.py`

```
curl -O https://raw.githubusercontent.com/vaproloff/tion_home_assistant/master/docs/captcha_proxy_https.py
sudo python3 captcha_proxy_https.py https://<домен>
```

Если в адресе есть порт, укажите его: `https://<домен>:<порт>`. В Windows — `curl.exe` и `py` без `sudo`, как в способе для http. Выключить: Ctrl+C.

Ошибка 502 «certificate verify failed» значит, что Python не доверяет сертификату адреса. На macOS с Python с python.org один раз запустите `Install Certificates.command` из папки Python в «Программах» (Applications). Самоподписанный сертификат скрипт не примет: нужен адрес с настоящим сертификатом.

### Готовые альтернативы

Если у вас уже есть `mitmproxy` или Caddy, можно обойтись без скрипта:

```
mitmdump --mode reverse:https://<домен> -p 80
```

```
caddy reverse-proxy --from :80 --to https://<домен> --change-host-header
```

Обе команды по умолчанию слушают все сетевые интерфейсы компьютера, а не только `127.0.0.1`: пока они работают, Home Assistant на этом порту доступен всей вашей локальной сети. Для `mitmdump` добавьте `--listen-host 127.0.0.1`; Caddy остановите (Ctrl+C) сразу после входа. Если сомневаетесь, используйте наш скрипт: он слушает только `127.0.0.1`.

## Проверка

Когда проброс включён, откройте в браузере `http://localhost/manifest.json`. Если открылся длинный JSON и в нём есть `"name":"Home Assistant"`, проброс работает. Можно открыть и `http://localhost/` в приватном окне: появится страница входа Home Assistant.

Входить в сам Home Assistant через `localhost` не нужно. Через `captcha_proxy_https.py` его интерфейс и не заработает: скрипт пропускает только то, что нужно странице капчи, поэтому после входа будет «Unable to connect to Home Assistant». Это нормально. Пока браузер грузит интерфейс, скрипт может несколько минут печатать запросы к файлам: это тоже нормально.

Если ничего не открылось, проверьте:
- команда ещё работает и не написала ошибку;
- порт 80 свободен (его может занимать IIS, Skype или другой веб-сервер);
- адрес Home Assistant указан верно: браузер должен открывать его и напрямую.

## Вход

1. Не выключая проброс, добавьте интеграцию Tion (`Настройки` -> `Устройства и службы` -> `Добавить интеграцию` -> Tion) или откройте повторную авторизацию. Home Assistant открывайте по его обычному адресу, не по `localhost`.
2. Введите почту и пароль, а в поле «Адрес страницы капчи» укажите `http://localhost` (без порта и пути).
3. Нажмите «Отправить». Страница с капчей откроется в новом окне уже по адресу `http://localhost/...`. Пройдите проверку, если она появится. Страница напишет «Готово, вернитесь в Home Assistant» и закроется сама, а Home Assistant перейдёт к вводу кода из письма.
4. Введите код из письма. Вход выполнен.
5. Выключите проброс (команда выключения указана в способе, либо Ctrl+C). Он нужен только на время капчи. Home Assistant сам продлевает сессию Tion. Запрос на повторный вход появится, если Tion явно отклонит обновление сессии (форма «Tion отклонил сохранённую сессию»: войдите заново), или если обновление не удаётся больше часа (форма «Tion больше часа не продлевает сессию»: запрос снимется сам, когда связь восстановится, а вход нужен, только если он держится больше суток).

Адрес запоминается в записи интеграции, и при повторной авторизации поле уже заполнено им. Проброс при этом всё равно нужно включить заново.

## Почему так

Приложение Tion само живёт на `localhost`, и сервер Tion проверяет, с какого адреса открыта страница с капчей. Мы ничего не подменяем: страница капчи действительно открывается по адресу `http://localhost`. А `localhost` всегда означает компьютер, на котором работает браузер, поэтому проброс нужен на вашем компьютере: он превращает `http://localhost/` в окно в ваш Home Assistant.
